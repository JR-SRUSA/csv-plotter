Goal Implement a client‑side data model, storage, services, and UI hooks for a motorsports webapp. The system must support Sessions, Vehicles, Riders, Users, Notes, Files, Setups, KPIs, and Media. Use IndexedDB as the canonical local store (with a minimal localStorage fallback only if IndexedDB is unavailable). Data must be exportable/importable as a single JSON bundle compatible with the existing website export and reimport workflow. The existing quick‑plot CSV behavior must remain unchanged: opening a CSV plots immediately; users can continue adding CSVs and later attach them to sessions via an Add to Session button in the file view.

Use IndexedDB as the standard storage backend. Implement a small fallback shim to localStorage only if indexedDB is not available.

Database name: motorsports_app_v1. Object stores: users, riders, vehicles, setups, sessions, notes, files, mediaIndex, appMetadata.

Include schemaVersion in appMetadata and run migrations on startup/import.

Data model and rules

General rules

All objects have id, created_at, updated_at.

Use ID references for relationships; avoid deep nesting.

IDs should be UUIDv4 or prefixed IDs (e.g., session_..., user_local_...) for readability.

Timestamps stored as ISO 8601 UTC strings.

Behavioral rules and UX

Setup versioning: when user edits setup for a vehicle, create a new Setup record with vehicle_id and timestamp. Do not modify historical Setup records. Provide getLatestSetup(vehicle_id, session_id?) helper to fetch the most relevant setup.

CSV quick plot: opening a CSV continues to plot immediately. Do not force session creation. In the file viewer (where parsed CSV and plot are shown), add an Add to Session button. The button opens a compact modal to select an existing session or create a new session and optionally tag the file, pick vehicle, pick rider, or add a quick note.

Add multiple CSVs: allow users to add more CSVs after the first; files are independent objects and can be attached to sessions at any time.

Notes author: author_id is optional. On first run create user_local_<id> and use as default author. If user logs in, provide migration UI to map user_local_* to user_*.

Camera permission: request navigator.mediaDevices.getUserMedia({ video: true }) only on explicit user action (Take Photo / Record Video). If denied, fallback to file picker. Store media as blobs in IndexedDB mediaIndex or as references to external URLs. Default export includes references only; includeMediaBlobs flag can embed base64 blobs.

KPIs: sessions include kpis array of { type, kpi }. Provide SessionService.addKPI(sessionId, {type, kpi}) and SessionService.getKPIs(sessionId).

Relationship rules
No deep nesting: all relations by ID arrays.

Setups separate: updating a Setup creates a new Setup object or version; do not mutate historical Setup objects referenced by past Files or Sessions unless explicitly requested.

Notes link to multiple sessions: note.session_ids is an array. When a note is added to multiple sessions, update both the note and each session’s note_ids list.

Files can belong to multiple sessions: file.session_ids array.

Deletion: deleting an object removes its ID from referencing objects; provide soft delete option.

Export, Import, Migration and Edge Cases
Export format

json
{
  "schemaVersion":"1.0",
  "exportedAt":"2026-09-16T11:00:00Z",
  "users":[...],
  "riders":[...],
  "vehicles":[...],
  "setups":[...],
  "sessions":[...],
  "files":[...],
  "notes":[...],
  "mediaIndex":[...],
  "appMetadata":{...}
}
Default: include media references only. Optional includeMediaBlobs: true to embed base64 blobs.

Import behavior

Validate schemaVersion.

options.replaceExisting true wipes local DB and imports bundle.

If ID collisions occur and replaceExisting is false, generate new IDs and return a mapping { oldId: newId }.

options.migrateLocalUsers allows mapping user_local_* to user_* when a user claims local data. Provide UI to review mappings before applying.

Support dryRun to validate and preview changes.

Migrations

Store schemaVersion in appMetadata. Run migration scripts on startup or import when schemaVersion differs.

Edge cases

Large media: prefer references; warn user about export size when including blobs.

Offline: all operations must work offline; queue cloud sync tasks if implemented later.

Timezones: store UTC ISO strings; display in local timezone in UI.

Permissions: camera permission requested only on explicit action.
